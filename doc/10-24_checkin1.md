## Data Pre-Processing
We downloaded the fastq for one sample using SRA and `fasterq-dump`. We then aligned the fastq using `bwa mem` with default settings as followed in the paper using a batch script [here](https://github.com/gpmoorhead1/Fly_Genome_Architecture/blob/gm_work/analysis/readmapping/fly_alignment.sh). It took quite some time for the fastq to download but alignment took faster than we expected, although it seems to have run successfully. We suspect that it took less time than expected because it is a smaller genome (drosophila). We then used samtools to index and sort the bam for further downstream analyses. We uploaded these commands in the `analysis/readmapping` directory.

We then moved on to using `pairtools` for processing the reads. According to Mohana et al 2023, they used `pairtools` to parse, sort, and deduplicate the reads. Based on the tutorials on the `pairtools` github, it seems clear that they are referring to the `parse`, `sort`, and `dedup` commands which seem to be run sequentially in that order. In the methods section of Mohana et al, the authors write that they used this with “default settings”. Normally, I would take this to mean that they did not use any additional flags while running these commands, but the default example documentation on the `pairtools` github uses some additional, non-required commands. As of now, we are investigating what those additional flags mean and if they are necessary, while running the `pairtools` processing commands in the background.


## Post-Pairtools Work:
In parallel, we wanted to become familiar with the pipeline that would need to be used to take the paired-end ligation product reads and populate a genomic contact matrix with them (for visualization with a heat map). Working with an example set of aligned reads from yeast, we ran a brief pairtools pipeline to identify and sort ligation products into a .pairs file(data and code downloaded/adapted from the ‘Quickstart’ section of the Pairtools [readthedocs.io](https://pairtools.readthedocs.io/en/latest/quickstart.html) website). Then, we used a set of commands inspired by those in the ‘Quickstart’ section of the cooler documentation to generate a .cool file looking at genome-wide yeast chromatin interactions at 10kb resolution. All of the commands detailed in this section are stored in a [bash script](https://github.com/gpmoorhead1/Fly_Genome_Architecture/blob/gm_work/analysis/testing/test-pairtools-and-cooler.sh) titled “test-pairtools-and-cooler.sh”, but were run from the command line independently, so this is more of an archive of commands. The final command listed prints the counts in bins from a defined pair of regions in the .cool file we generated, and looking at this confirms that we’re getting contacts placed into bins. We’ve begun to explore a Bioconductor package in R for visualizing Hi-C data, but initial contact maps generated have little information baked into them ([code here](https://github.com/gpmoorhead1/Fly_Genome_Architecture/blob/gm_work/analysis/testing/exploreHiCvisualization.R)). So far, contact maps seem to have very little visualizable data off of the main diagonal, but it’s unclear whether this is due to the visualization pipeline or the data we’re working with. Upon further inspection, it appears that there are only about ~20,000 ligation products in the yeast dataset supplied by the pairtools documentation website. Binning the 12 megabase yeast genome into 10kb bins would yield ~1200 bins, meaning the contact map’s upper triangle has 12002/2 bins, or roughly 700,000. As such, it makes sense that most of the bins seem unpopulated or with only 1-5 contacts within them. It makes sense that a website like the pairtools documentation might provide users with a trimmed down, less populated dataset of aligned Hi-C reads, such that they can be easily worked with on home computers.


To ensure that this is a property of the dataset and not the visualization pipeline used, we plan to test at least one other .cool file viewer, going through softwares/browser tools linked on the 4D nucleome website. Then, we plan to tweak the cooler pipeline to test different data sets (or our paired Drosophila reads, whichever comes first).
